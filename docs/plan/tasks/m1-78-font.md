# M1-78 — The font, baked and embedded

Phase: G | Status: not started
Prerequisites: M1-28

## Purpose

The MFD needs text. The owner asked whether the font can be part of the project
rather than something the runtime goes looking for, and it can — all the way
into the executable.

## What to implement

- **Commit `DejaVuSansMono.ttf`** from release 2.37, with its licence file
  beside it. Bitstream Vera derived: permissive, bundling inside a larger
  package explicitly allowed, notice required, derivatives must be renamed. The
  licence text is committed, not linked, and `THIRD_PARTY.md` records it.
- **`tools/fontbake/`**: rasterises the glyph set with `stb_truetype` — already
  pinned — into a single-channel atlas plus a metrics table (advance, bearing,
  and the atlas rectangle per glyph). The glyph set is stated explicitly: ASCII
  32–126 plus the degree sign and the characters the readouts actually use.
  Baking every glyph in the font would be a megabyte of atlas for characters
  nothing prints.
- **The atlas is embedded in the executable** as a generated byte array, written
  by CMake into a header at build time. No runtime font file, no asset path, and
  nothing for a user's directory layout to break.
- **The bake is deterministic**, and that is asserted by hashing the output:
  same font, same settings, same bytes. It is what makes the embedded array
  reviewable — a diff that changes it should have a reason.
- Signed-distance-field or plain coverage: **plain coverage at a fixed size**,
  chosen because an MFD is a fixed-size instrument and SDF buys scaling this
  milestone does not need. Written down so the decision is visible when scaling
  is eventually wanted.

## Out of scope

Runtime rasterisation, arbitrary sizes and DPI scaling — the upgrade path is
`stb_truetype` at runtime, and it is named here so it is a choice later rather
than a surprise. Kerning pairs; a monospace font does not need them. Non-Latin
scripts.

## Tests

`tests/test_font_atlas.cpp`, headless.

- **The metrics table is complete and consistent**: every glyph in the stated
  set has an entry; every atlas rectangle lies inside the atlas; no two glyphs
  overlap; advances are positive.
- **Monospace really is**: every glyph in the set has the same advance width,
  which is a property of this font and a check on the bake.
- **The hash matches**: the embedded atlas equals the freshly baked one, so a
  stale generated header cannot silently ship.
- **A known glyph is right**: the coverage of a chosen glyph — a full block or a
  capital letter — has the expected ink fraction within a tolerance, so an
  all-zero or all-one atlas fails rather than passing every structural check.

## Verification

The standing rules, plus opening the atlas as an image once and looking at it.
An atlas that is subtly wrong — wrong gamma, off-by-one packing — is instantly
visible and almost impossible to assert.

- [ ] The atlas has been looked at once and is right.
